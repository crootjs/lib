# Changelog

All notable changes to CrootJS. Versions are git tags, served by jsDelivr as `https://cdn.jsdelivr.net/gh/crootjs/lib@<version>/<module>.js`; each is also a [GitHub release](https://github.com/crootjs/lib/releases).

## [0.0.28](https://github.com/crootjs/lib/releases/tag/v0.0.28) - 2026-11-11

**PMTiles on servers that break HTTP Range**

- **mapoffline.js** - GitHub Pages gzip-compresses `.pmtiles` files and cuts ranges from the compressed bytes, so browsers reject or corrupt the pieces; the 0.0.27 offline example failed live because of it. When a Range request fails or returns the wrong length, the file is now downloaded whole once and read from memory, with a console warning. Covered by a new test that simulates such a server.

## [0.0.27](https://github.com/crootjs/lib/releases/tag/v0.0.27) - 2026-11-11

**Address search, offline PMTiles maps, 3D models on the map, skinning, Draco, AR, English docs**

- **mapsearch.js (new)** - `searchPlace`, `reverseGeocode` and `addSearchControl`: place and address search with OpenStreetMap's Nominatim (rate-limited to 1 request per second, search on Enter only, OSM attribution under the results) or your own server/provider.
- **mapoffline.js (new)** - `openPMTiles(url | File)`: a basemap from one PMTiles v3 raster file, read with HTTP Range requests from a static host, or from a file on the device with no internet. Checked against the official PMTiles sample.
- **mapmodel.js (new)** - `addModel`: a glTF/GLB model at its coordinates on the map, true to scale in meters, with heading, pitch, click (8 px tolerance) and a `minZoom`. Re-exports `model3d.js`.
- **map.js** - `tiles` (and `labels`) also accept an object `{ getTile(z, x, y) }` returning a Blob, URL or null.
- **model3d.js** - skinning (up to 64 joints per mesh; animations bend skinned meshes; picking and bounds follow the pose) and Draco-compressed models (`KHR_draco_mesh_compression`, decoded by Google's official decoder, downloaded only when needed; `dracoDecoder` option to self-host it).
- **model3dtools.js** - `addARButton` and `getARLink`: "Lihat di AR" opens Google Scene Viewer on Android, or AR Quick Look on iPhone/iPad when a `.usdz` is given.
- **Docs in English** at https://croot.js.org/docs/en/, with a language link on every page.
- **tests/** - 50 tests, including PMTiles, search, map models, skinning and Draco (skipped when the decoder server is unreachable).

## [0.0.26](https://github.com/crootjs/lib/releases/tag/v0.0.26) - 2026-11-11

**Map drawing, awaitable api.js, tests and type declarations**

- **tests/** - browser test page for the modules (`tests/index.html`, open it through any local server or at https://croot.js.org/lib/tests/), run headless in CI on every push and tag.
- **mapdraw.js (new)** - draw points, lines and polygons on the map and edit them (drag vertices, insert from segment midpoints, delete by double-click or touch long-press); results are GeoJSON. `addDrawControl` (tool buttons with hints and Selesai/Hapus titik/Batal for touch), `startDrawing`, `editFeature`.
- **api.js** - `getJSON`, `postJSON`, `putJSON` and `deleteJSON` also return a Promise of the same `{ status, data }`, so they can be awaited (`responseFunction` may be `null`). The Promise never rejects; network failure is still `status: 0`.
- **crootjs.d.ts (new)** - TypeScript declarations for every module, matched to jsDelivr URLs of any version, for editor autocomplete. Generated by `tools/build-types.py`.
- **CLAUDE.md, conventions** - a mandatory "no AI slop" section for coding agents: no invented APIs, no dead code or fake content, verify in a browser before saying it is done.
- **model3d.js** - nodes that are not part of the scene (for example parts left out by `exportGLB`) are no longer counted in `triangles` and can no longer be clicked. Found by the new tests.

## [0.0.25](https://github.com/crootjs/lib/releases/tag/v0.0.25) - 2026-11-11

**3D animation, exploded view and cross-sections**

Tools for interactive 3D learning material.

**model3dtools.js**
- `getAnimations(id)` and `playAnimation(id, nameOrIndex, options)` play the animations stored in a glTF file (node translation/rotation/scale; STEP, LINEAR and CUBICSPLINE), with `play`, `pause`, `stop`, `seek(seconds)` and `setSpeed`. `seek` works while paused, for a time slider.
- `explodeModel(id, amount, options)` pulls parts away from their center like an assembly drawing; `amount` 0 to 1 works directly from a slider and 0 restores the exact positions.
- `addSection(id, options)` slices the model with a plane (`axis`, `position`, `flip`, `color`) to show the inside; the cut side cannot be clicked, and the cut face is drawn solid.

**model3d.js** - clip plane support in the shader and in picking; `fitView` accepts an array of part names.

Example: [3D learning material - anatomy of a BTS tower](https://croot.js.org/examples/3d/belajar/).

## [0.0.24](https://github.com/crootjs/lib/releases/tag/v0.0.24) - 2026-11-11

**3D model viewer without Three.js**

**model3d.js (new)** - a glTF 2.0 viewer (`.glb` and `.gltf`) written from scratch, with no Three.js: its own binary GLB parser, matrix math and shaders, on WebGL2 with an automatic WebGL1 fallback. About 14 KB gzipped.

- `createViewer(id, options)` and `loadModel(id, url | File | ArrayBuffer, responseFunction)` (also awaitable); the camera fits the model automatically.
- Orbit, pan and zoom with mouse, touch and keyboard; double-click to focus a point; optional auto-rotate.
- `onModelClick` reports the part that was clicked, its path in the node tree and the 3D point.
- Parts (glTF nodes) by name: `getParts`, `setPartColor`, `setPartVisible`, `highlightPart`, `getPartTransform` / `setPartTransform` (position, Euler or quaternion rotation, scale).
- Camera: `fitView`, `setCameraView`, `getCameraView`, `setAutoRotate`.
- Supports textures, vertex colors, transparency (`BLEND`/`MASK`), double-sided materials, interleaved and sparse accessors, `KHR_materials_unlit`, `KHR_materials_emissive_strength` and `KHR_mesh_quantization`. Draco/meshopt compressed models fail with a clear message.

**model3dtools.js (new)** - `addHotspot` (HTML labels pinned to a part or point, dimmed when hidden behind the model), `enableTransform` (translate/rotate/scale gizmo for mouse and touch, Shift snaps rotation to 15°), and `exportGLB` / `downloadGLB` (the edited model, with transforms, colors and hidden parts, as a single `.glb`).

Examples: [3D model viewer](https://croot.js.org/examples/3d/viewer/) and [BTS antenna editor](https://croot.js.org/examples/3d/editor/).

## [0.0.23](https://github.com/crootjs/lib/releases/tag/v0.0.23) - 2026-10-31

**Right-click context menu for maps**

**mapcontrol.js** - `addContextMenu(id, items, options)`: a right-click menu for GIS actions. It opens on right-click, a 0.5 s touch long-press (also on iPhone) or Menu/Shift+F10 on the focused map. `items` may be a function `(position, feature) => [...]` so the menu changes with what is under the pointer. Items support icons, `disabled`, `danger`, separators and submenus, plus built-ins `"coordinates"` (shows and copies lat, lng), `"center"`, `"zoom-in"` and `"zoom-out"`. Keyboard navigation, ARIA, dark mode, edge flipping and larger touch targets.

**map.js** - `onMapContextMenu(id, fn)` for building your own menu. The browser's menu is only suppressed while a listener exists, and never inside popups or controls. A tap followed by a long-press no longer zooms the map.

**mapheat.js** - `addGridMap` returns `cellAt(position)`, for showing a cell's value in the context menu.

## [0.0.22](https://github.com/crootjs/lib/releases/tag/v0.0.22) - 2026-10-31

**Heatmaps and coverage grids**

**mapheat.js (new)** - heatmaps and coverage grids from point data (GeoJSON points or `[lng, lat, value]` arrays), drawn on one canvas above the basemap and below `addGeoJSON` layers.

- `addHeatmap(id, data, options)` - smooth density, blue to red. Options `weight`, `radius` or `radiusMeters`, `max` (default: highest density in view), `scale` (`linear`/`sqrt`/`log`), `gradient`, `opacity`, `legend`. 50,000 points redraw in about 15 ms.
- `addGridMap(id, data, options)` - points binned into square or hexagon cells (`cellSize` in screen pixels, or `cellMeters` fixed on the ground), each colored by the mean/max/min/sum/count of its values through `breaks` - an nPerf-style signal coverage map. Clicking a cell shows its value and calls `onClick(cell)`. Optional legend.

Both return `{ setData, setOptions, show, hide, remove }`.

**maptools.js** - `exportMapImage` includes heatmaps and grids in the PNG.

## [0.0.20](https://github.com/crootjs/lib/releases/tag/v0.0.20) - 2026-10-31

**Picture-card basemap picker**

Requested by the NetDet maps team: a basemap picker like the layer picker in Google Maps / nPerf.

**mapcontrol.js** - `addBasemapControl(id, basemaps, { style: "cards" })` shows the active basemap as a picture card; hovering (mouse) or tapping opens a grid of cards. Card images come from a basemap's `thumbnail`, or its own tile at `thumbnailCenter`/`thumbnailZoom`, with its label tiles on top. Options `trigger`, `columns` (at most 2 on screens up to 640 px), keyboard and ARIA support, and dark mode. The default `style` stays `"list"`.

## [0.0.18](https://github.com/crootjs/lib/releases/tag/v0.0.18) - 2026-10-30

**Canvas renderer, measuring, image overlays and PNG export**

The rest of the NetDet maps brief: technical and survey maps.

## [0.0.17](https://github.com/crootjs/lib/releases/tag/v0.0.17) - 2026-10-30

**Named layers, labels and basemap switching**

Requested by the NetDet maps team, whose app had to work around these.

**map.js - basemaps** - `maxNativeZoom` (overzoom: tiles of that level are scaled up instead of left blank), `labels` (transparent label tiles over the base tiles, for satellite + labels = hybrid), `{s}`/`{r}`/`{-y}` in tile URLs with a `subdomains` option, and `errorTiles` for tiles that fail to load. New `setTiles(id, tiles, options)` swaps the basemap without recreating the map: layers, markers, the open popup and the view stay, and the old tiles stay until the new ones have loaded, so the map never blinks. New `showLayer`, `hideLayer`, `setLayerStyle`, `setLayerOrder`, `removeLayer`, `getLayers`. Styles gain `strokeDasharray`, `lineCap`, `lineJoin`; `fitMap` padding may be per side.

**mapmarker.js** - `anchor` accepts top, left, right and the four corners, plus `offset: [dx, dy]`.

**mapcontrol.js** - `addBasemapControl` (radio list calling `setTiles`) and `addLayerControl` (checkboxes for named layers), both with a collapsed mode.

## [0.0.16](https://github.com/crootjs/lib/releases/tag/v0.0.16) - 2026-10-13

**Clustering and live tracking**

**mapcluster.js (new)** - `addCluster(id, geojson, options?)` draws the Point/MultiPoint features of very large datasets as count bubbles that split as the map zooms in. Grid clustering per zoom level, computed lazily, and only clusters in view get DOM elements, so 100,000 points pan smoothly. Options: `radius`, `color`, `popup`, `onClick`; returns `remove()`.

**mapcontrol.js - live tracking** - `trackUser(id, responseFunction?, options?)` watches the position continuously and returns `stop()`; the callback gets `{ position, accuracy, speed, heading, timestamp }` on every fix (`speed` m/s and `heading` degrees may be `null`), or `null` once if permission is denied. The map follows the position (`options.follow`, default `true`) until the user pans it manually. `addTrackButton(id, responseFunction?, options?, corner?)` is a toggle button for it.

**map.js - onTap** - `onTap(element, fn)` lets an overlay element handle its own tap: the map does not treat it as a map click and does not close the open popup, while a drag that starts on it still pans the map. The cluster bubbles are built on it.

## [0.0.14](https://github.com/crootjs/lib/releases/tag/v0.0.14) - 2026-10-13

**New module: map.js**

**map.js (new)** - a slippy map written from scratch, with no Leaflet.

- Raster tile basemap (OpenStreetMap by default, any `{z}/{x}/{y}` URL, or none) with GeoJSON drawn as SVG on top.
- `createMap` / `removeMap`, `addGeoJSON` (style and popup options, returns `remove()`) / `clearMap`, `fitMap` / `setMapView` / `getMapView`, `onMapClick` (position and the clicked feature), `showPopup` / `closePopup`.
- Drag, wheel and trackpad zoom, pinch, double click, zoom buttons and keyboard. Tiles of the previous zoom level stay, scaled, until the new ones load.
- All positions are `[longitude, latitude]`, the same order as GeoJSON. Popup text is inserted as text, never HTML.
- Injects its own stylesheet and re-exports `geo.js`, so a map page needs a single import.

## [0.0.13](https://github.com/crootjs/lib/releases/tag/v0.0.13) - 2026-10-13

**New module: geo.js**

**geo.js (new)** - read GeoJSON from a URL or a local file.

- `getGeoJSON(url, responseFunction, tokenkey?, tokenvalue?)` follows `getJSON`'s `{ status, data }` callback, but sends no headers unless a token is given, so static hosts like raw.githubusercontent.com work without a CORS preflight. GitHub file-page links are rewritten to their raw URL.
- `readGeoJSONFile(id, responseFunction)` reads an `<input type="file">`; `parseGeoJSON(input)` validates a string or object.
- Any input - FeatureCollection, Feature, bare geometry or an array - comes out as a FeatureCollection whose features always have `properties`. Invalid features are skipped and logged instead of failing the whole file.
- `getBBox`, `getCenter`, `getPropertyKeys`, `getCoordinates` and `toLatLng` for summarising data and feeding a map or table.

## [0.0.12](https://github.com/crootjs/lib/releases/tag/v0.0.12) - 2026-09-14

**QR login no longer drops late scans**

**auth.js - QR login no longer drops late scans** - when the QR code rotated, the old socket was closed at the same instant, so a scan sent in the last seconds of a cycle reached a session with nothing behind it and the backend answered "session expired". The old socket now stays open for `wauthparam.graceperiod` seconds (default 15) so a late scan still logs in.

A dropped connection (flaky network, backgrounded tab, backend redeploy) is now reported: the QR is swapped for a refresh button, rotation stops, and the new optional `wauthparam.onconnectionlost` callback is called. Also fixes a socket that rotated before its handshake finished and was never closed.

## [0.0.11](https://github.com/crootjs/lib/releases/tag/v0.0.11) - 2026-09-11

**Error callback for insertHTML and renderHTML**

Both functions only had a success callback, so after v0.0.10 a failed load no longer hung but the caller still could not detect it. An optional last parameter has been added:

```js
insertHTML(url, id, runFunction, errorFunction)
renderHTML(id, url, callback, errorCallback)
```

It is called with an `Error` when the element does not exist, the reply is non-2xx, the network fails, or the request times out. On failure the element is left unchanged and the success callback is not called. Existing three-argument calls keep working and log failures as before.

An exception thrown inside your own success callback is not reported to the error callback, so a bug in your code is not mistaken for a failed load.

**Behavior change:** `insertHTML` now treats a non-2xx reply as a failure. It previously injected the server's error page, a 404 page for example, into the element and then called `runFunction` as if the load had succeeded. `renderHTML` already behaved this way.

Docs: https://croot.js.org/docs/api/ and https://croot.js.org/docs/element/

## [0.0.10](https://github.com/crootjs/lib/releases/tag/v0.0.10) - 2026-09-11

**Failure handling for the remaining api.js and element.js requests**

v0.0.9 only covered the four JSON functions. Every other network call in the library had the same problem.

* `postFile`, `postFileWithHeader`, `postFileJSON`: a network failure was only logged, and `JSON.parse` threw on a non-JSON reply. Either way the callback never fired. They now call back with `null`, or `{status: 0, data: null}` for `postFileJSON`.
* `getFileBytesWithHeader`: on a 200 reply it read `response.arrayBuffer()` and then discarded it, so the function never delivered file bytes to anyone. It now passes the `ArrayBuffer` to the callback.
* `getFileWithHeader` and `getFileBytesWithHeader`: a non-JSON error body previously stopped the callback from firing; network failures now call back with `{status: 0}`.
* `insertHTML`: the error message blamed a missing element for every failure, including network errors. The element is now checked before the request.
* Added the 15 second timeout to every request in `api.js`, and to `renderHTML`/`replaceTag` in `element.js`.

Docs: https://croot.js.org/docs/api/

## [0.0.9](https://github.com/crootjs/lib/releases/tag/v0.0.9) - 2026-09-10

**getJSON and friends no longer fail silently**

`getJSON`, `postJSON`, `putJSON` and `deleteJSON` swallowed every failure: the `.catch` only wrote to the console and never called `responseFunction`, so the caller had no way to know a request had failed. A server that accepted the connection but never replied left the call pending indefinitely, because `fetch()` has no timeout of its own.

* `responseFunction` is now always called. On a network failure, CORS rejection or timeout it receives `{status: 0, data: null}`. `0` is never a real HTTP status, so it can be used to tell a failed request apart from a 4xx/5xx reply.
* Every request aborts after 15 seconds.
* A malformed JSON body no longer prevents the callback: the real HTTP status is passed through with `data: null`.

Docs: https://croot.js.org/docs/api/

## [0.0.8](https://github.com/crootjs/lib/releases/tag/v0.0.8) - 2026-09-10

**New module: toast.js, plus serializeForm**

* New `toast.js`: notifications with no external dependency, as an alternative to loading SweetAlert2 just to show a message. Provides `toast(message, type, duration)` and the shortcuts `toastSuccess`, `toastError`, `toastWarning`, `toastInfo`. Each returns a `dismiss()` function, and `duration: 0` keeps the toast until you dismiss it, which suits a loading state. The CSS is injected by the module itself, so there is no separate stylesheet to import.
* New `serializeForm(id)` in `element.js`: returns every named form field as one `{name: value}` object, so `getValue()` no longer has to be called field by field before `postJSON()`. Disabled fields and file inputs are skipped; file uploads need `postFile`/`postFileJSON`.

Docs: https://croot.js.org/docs/toast and https://croot.js.org/docs/element/

## [0.0.7](https://github.com/crootjs/lib/releases/tag/v0.0.7) - 2026-09-10

**New module: debounce.js**

Adds `debounce.js`:

* `debounce(fn, delay)` - runs `fn` only after the caller stops triggering it, for search-as-you-type and similar input handling.
* `throttle(fn, delay)` - runs `fn` at most once per interval, firing immediately and again at the end of the window so the last call's arguments are not lost. Useful for `scroll`, `resize` and `mousemove`.

Docs: https://croot.js.org/docs/debounce

## [0.0.6](https://github.com/crootjs/lib/releases/tag/v0.0.6) - 2026-09-10

**New module: storage.js**

Adds `storage.js` for `localStorage` and `sessionStorage`:

* `setLocal`, `setLocalWithExpireDay` / `Hour` / `Second`, `getLocal`, `deleteLocal`
* `setSession`, `getSession`, `deleteSession`

Values are serialized with JSON automatically, so objects and arrays can be stored directly. `localStorage` entries support an optional expiry, which the browser's own API does not provide; expired entries are removed on read.

Docs: https://croot.js.org/docs/storage

## [0.0.5](https://github.com/crootjs/lib/releases/tag/v0.0.5) - 2026-09-09

**Restores the window.catcher fallback**

`websocket.js` again calls a global `window.catcher(message)` when no `onMessage` callback is passed. v0.0.4 replaced that global with an explicit callback parameter, which broke the pattern documented for WhatsAuth. Both styles now work: pass `onMessage` if you have one, otherwise define `window.catcher`.

## [0.0.4](https://github.com/crootjs/lib/releases/tag/v0.0.4) - 2026-09-09

**Repairs the library so it actually loads**

**This release fixes bugs that made parts of the library unusable.**

* `auth.js` could not be parsed as an ES module at all: it imported `setCookieWithExpireHour` from `cookie.js` and also declared its own copy, which is a `SyntaxError`. Any page importing it failed to load.
* `config.js` imported from `whatsauth.js` and `helper.js`, two files that do not exist in this repo, and `DefaultSuccesser` referenced undefined variables.
* `websocket.js`'s `openWebSocketSetId` always returned `undefined` because the socket was assigned inside a `.then()` callback and returned outside it, so `sendMessagetoWebSocket`/`closeWebSocket` could never receive a usable socket.
* Removed duplicated code: `IsMobile`/`isMobile` existed twice, and the four JSON functions in `api.js` were four copies of the same request logic.

**Breaking:** `openWebSocketSetId` now returns a `Promise` that resolves with the `WebSocket`. It previously returned `undefined` in every case, so no working code can depend on the old behavior.

## 0.0.1 - 0.0.3 - 2026-03-03 to 2026-04-13

First releases: `element.js`, `api.js`, `cookie.js`, `url.js` and the other core helpers, the WhatsAuth QR login (`auth.js`, WebSocket handling, configuration), and Google Sign-In with SweetAlert2 notifications.
